# TEKO STORE — تسجيل الطلبات ولوحة المالك

**الحالة الحالية: مجهز على GitHub فقط — لم يُفعّل على Supabase.**
استقبال ZIP وإرسال رابط واتساب مستمران. ميزة تسجيل الطلبات في قاعدة البيانات مغلقة عمدًا في order-cloud-config.js.

## 1. تجهيز قاعدة البيانات
افتح SQL Editor في Supabase، وانسخ محتوى:
supabase/migrations/20261121_teko_orders.sql

ينشئ جدول public.teko_orders مع RLS وبدون صلاحيات قراءة عامة، لحفظ بيانات العميل والهودي والمقاسات والكمية وحالة الطلب ومسار ZIP الخاص. لا يتم تخزين رابط ZIP الموقّع لانتهاء صلاحيته.

## 2. تحديث خدمة رفع الطلب
افتح:
supabase/functions/teko-order-link/index.ts

انشر النسخة الجديدة في Edge Functions > teko-order-link > Code.
تقبل هذه النسخة حقل order اختياريًا داخل finish بعد إثبات وصول ملف ZIP. ثم تحفظ بيانات الطلب وتعيد registered: true.
العملاء الحاليون الذين لا يرسلون الحقل order يظلون مدعومين، ولا تتغير عملية الرفع الحالية.
اترك Verify JWT = OFF مثل إعداد الوظيفة الموجودة.

## 3. إعداد حساب المالك
Supabase > Authentication > Users: أنشئ حساب المالك ببريد إلكتروني وكلمة مرور قوية.
انسخ UUID من User ID وأضفه في Edge Functions > Secrets باسم:
TEKO_OWNER_UID

تحقق الخدمة من هوية Supabase Auth وUser ID على الخادم، وليس اعتمادًا على البيانات المرسلة من المستخدم.

## 4. نشر خدمة الإدارة
انشر الملف:
supabase/functions/teko-admin-orders/index.ts

اسم الوظيفة: teko-admin-orders، واجعل Verify JWT = OFF، إذ يقوم الكود نفسه بالتحقق من JWT ومعرف المالك.
تتيح هذه الوظيفة عرض قائمة الطلبات، التفاصيل، تحديث الحالة، وإنشاء رابط تنزيل ZIP جديد لمدة 15 دقيقة.

## 5. إكمال إعداد واجهة المالك
افتح owner-config.js على GitHub، وأضف مفتاح Supabase Publishable العام في publicKey.
مكانه: Supabase > Project Settings > API Keys.
هذا المفتاح العام فقط يجوز تضمينه في الواجهة.

ممنوع إضافة أي مفتاح خاص مثل sb_secret_ أو service_role أو TEKO_HMAC_SECRET أو TEKO_CRON_SECRET أو مفاتيح Vault.

رابط لوحة المالك بعد تفعيلها:
https://oa1963507-commits.github.io/teko-store/owner.html

الجلسة تُخزن في ذاكرة الصفحة فقط؛ لا تُخزن كلمة المرور أو access token في localStorage.
لوحة المالك خاصة، وتظهر بيانات العميل فقط بعد تحقق الخادم من هوية المالك.

## 6. الاختبار والتفعيل
1. بعد تنفيذ SQL ونشر الوظائف، اختبر تسجيل الدخول إلى لوحة المالك.
2. اختبر تسجيل طلب جديد بملفات تجريبية.
3. تحقق من ظهور السجل داخل قاعدة البيانات ولوحة المالك، ومن إمكانية تغيير حالته.
4. تحقق من أن مستخدمًا غير مالك لا يستطيع رؤية الطلبات.
5. بعد نجاح الاختبارات، غيّر databaseOrdersEnabled إلى true في order-cloud-config.js وحدّث رقم Cache في index.html.

**لا تغير العلم الآن.** تفعيل الخاصية قبل نشر قاعدة البيانات والوظائف سيؤدي إلى تعذر تسجيل الطلب.

## ملاحظات
- وظيفة تنظيف الملفات teko-orders-cleanup تزيل ZIP بعد 7 أيام، لا سجل الطلب.
- الأسعار والعمليات المالية في الطلب بيانات مبدئية مقدمة من الواجهة، وليست إثبات دفع.
- راعِ سرية عناوين وأرقام العملاء، ولا تشارك لقطات شاشة بها بيانات فعلية.
